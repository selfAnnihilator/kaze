# Kaze interface contract

Both production themes hide scrollbar tracks and thumbs throughout the interface, including dialogs and nested lists. Preserve native overflow, wheel/touchpad scrolling, keyboard navigation and the existing shelf arrows.

## Startup

Each theme has its own startup animation. Show a neutral, static app icon while reading the saved preference, then start only the selected theme's introduction. Load App code concurrently with that read and the introduction; mount the functional shell directly in the saved theme.

Spatial uses warm charcoal, a subtle rotating/pulsing ring and bold, spaced KAZE lettering. The word fades from beginning to end with overlapping fades and a slight airy drift, keeping the centered composition still. Its introduction lasts two seconds.

Brutalist uses the same airy, left-to-right word reveal and two-second timing, styled for its matte surface, hard square frame with red rules, heavy compact KAZE lettering, and an indeterminate red loading sweep. Keep the motion family similar in both themes while matching their visual identities. Neither theme uses typing steps or a cursor. Longer loads retain the selected composition and moving loading indicator. Reduced motion shows each theme's complete still composition immediately, without a forced introduction delay.

Use CSS transform/opacity animation and a single mount-only completion timer; never send reveal or animation ticks through App or playback state. Keep one stable accessible loading announcement, hide decorative letters from assistive technology, and unmount the animation when startup succeeds or displays a retryable error. A late settings response must not revive an already failed startup. Reuse the existing 256px launcher icon rather than generating a new mark. The standalone studies keep their own state and make no production startup queries.

## Familiarity controls

Spatial uses `FamiliarityDial`; Brutalist uses the thick horizontal `FamiliarityBar` requested on 2026-10-17. Both control the same production Flow steering value. They represent the existing 0–1 familiarity ratio in 0.05 steps, with Rediscover/Familiar endpoints and an accessible numeric value.

Dragging previews locally in the memoized control. Release commits through the existing callback and 250ms command debounce. Familiar favors played/liked songs, including online favorites; Rediscover includes less-heard online discoveries and forgotten tracks. Apply steering to generated upcoming slots immediately while preserving the current song, position and manual queue entries. Refresh the confirmed Flow label and queue after the command succeeds. Cancel restores the controlled value. The Brutalist bar computes its pointer position explicitly while captured: WebKitGTK suppresses native range dragging after pointer capture. Keep drag previews local, clamp outside movement, and commit once on release; blur or cancellation restores the controlled value. Arrow keys, Page Up/Down and Home/End adjust it without triggering global playback shortcuts. Preserve playback and the existing Flow lifecycle; this is a presentation change.

## Settings

Settings follows a single top-to-bottom path in both themes. The main page contains Interface Style, Window Close Behavior, Startup, Music taste, Music Folders, System & Storage and Account. Music taste, Music Folders and System & Storage open their own focused sections with a Back to Settings action, rather than horizontal tabs or expanded settings on the main page. Preserve the selected section on route return.

Keep style changes immediate with the existing persistence/error contract. Window close behavior stays on the outer page. Startup offers “Start in tray on login”, backed by the operating system login entry. Confirm saves before changing the switch and keep its state isolated in a memoized leaf; see [login startup](docs/login-startup.md) for registration, hidden launch and tray fallback behavior. Folder details retain add/remove/rescan actions, readable paths and track counts; virtualize lists over 50 folders. System & Storage shows actual temporary-audio usage and Clear Cache. Omit internal database/cache locations, provider/engine diagnostics, cloud endpoint/security explanations and onboarding test controls. Remove the old Audio Engine, Metadata Providers, Soulseek and Cloud tabs from the user-facing settings surface.

Log Out belongs in Settings, with the signed-in name and retryable error feedback. Clicking it opens a theme-appropriate modal asking This device or All devices, with short explanations and Cancel. Opening/cancelling/Escape must not send a logout command. Keep keyboard focus inside the modal, return it to the trigger on dismissal, and block repeated actions/dismissal while a request is pending. The existing Logout and LogoutAll commands own the two scopes; all-device revocation requires server confirmation before the local session is cleared. Profile retains avatar/name editing and listening statistics; guest sign-in remains available. Do not reload after a failed logout. A rejected rescan must release its busy state so the user can retry.

Spatial uses a centered, narrow reading column, warm surfaces, restrained orange and soft choice outlines. Brutalist centers its bounded settings column within the main pane, with left-aligned controls, compact uppercase section headings, hard rules and red accents. Keep theme choices compact and explicitly mark the selected option; omit decorative theme thumbnails, marketing captions and tiny sequence numbers. Group folder/storage navigation separately from editable controls, with clear Manage actions. Their CSS compositions are independent; shared semantic controls do not make one a restyled copy of the other. Both must remain usable at short desktop and narrow window sizes with stationary hover targets and visible keyboard focus.

## Library Moment

Library Moment's cover is a direct play/pause/resume action for its supplied `first_track_id`; Open record independently opens the album and leaves playback alone. Both themes expose these actions. The backend spotlights albums with real local-library members and reports their counted tracks, rather than catalog placeholders or an unset metadata total. Opening any album uses `GetAlbumDetails` and its exact album ID, including albums outside the cached first 200; do not fall back to a title search or silently require a cached album summary. The resulting track list stays windowed and keeps account-scoped feedback/source identities.

The Brutalist archive's large number follows its selected category: displayed albums, displayed tracks (including an opened album's exact membership), regular playlists or the active Liked Songs collection. Smart mixes and the special Liked Songs playlist do not count as regular playlists. Derive this from existing view data without introducing playback-driven state. Library Moment's direct song pointer also follows recommendation exclusions; a blocked featured recording hides that spotlight while manual album browsing remains available.

## Focus feedback

Keep visible focus when navigating with Tab/Shift+Tab. Mouse-clicked buttons must not gain a focus outline merely because an unrelated key was pressed afterward. `usePointerFocus` marks pointer-origin controls until focus leaves or Tab navigation begins; text fields and sliders retain their native focus behavior. Preserve DOM focus and keyboard activation rather than blurring controls or globally removing focus outlines. Track this through DOM listeners, without React state or playback-driven updates.

Space after a pointer action controls playback, rather than activating the clicked action again. Capture only that pointer-origin shortcut before control handlers; Tab/Shift+Tab restores ordinary Space activation. Typing, sliders, modified/composing keys and modal actions keep their own keyboard handling. Holding Space must not repeatedly toggle playback.

Album-spine titles and artists stay in separate single vertical lines with ellipsis and bounded type size; full metadata remains in the button's title and accessible name. All horizontal shelves share `useHorizontalDrag`: primary mouse movement past six pixels scrolls directly, captures outside release and suppresses the resulting card click. Ordinary clicks, arrows, wheel/touch and keyboard scrolling remain available. Restore scrolling styles on release/cancellation/blur, prevent native artwork dragging, retain windowing and keep pointer positions outside React state.

Adapt spacing, artwork and action groups to the available pane width/height before allowing content scrolling; never scale or zoom the entire interface. Navigation, account access and playback stay reachable independently of content scrolling. Dialogs stay inside the viewport and scroll internally. While overflow exists, neither wheel boundaries nor Page Up/Down change chapters. No resize/scroll state belongs in App.

## First-use recommendations and notices

After folder onboarding, offer a native, keyboard-contained taste dialog to accounts without useful listening/feedback signals. Let users search artists with a 250ms debounce and choose up to five artists and five genres. Require a choice to save, allow Skip for now (including Escape), persist the decision per account, and let users revisit choices in Settings → Music taste. Use the active theme's existing surfaces, typography and controls. The dialog must fit 800×600 and scroll internally, with loading, retry and save failure feedback. Do not start playback during setup.

Accounts with no history still get starter Home/Discovery/Flow/Daily/Discovery-mix picks when catalog data is available, including popular choices when setup is skipped. Keep recent-listening and history-dependent shelves honest. Artist/genre choices must not be described as recorded plays or likes.

Transport buttons and Space use the authoritative TogglePlayPause command. If neither a selected track nor queue exists, keep playback stopped and show “Select a song to play” for two seconds. Repeated empty clicks refresh a single ephemeral message, without adding notification history. Preserve queued starts, cold restored playback and normal pause/resume; use confirmed backend state instead of optimistic playing flags.

Dislike confirmations expire after five seconds, pausing for hover, keyboard focus and a pending Allow again request. The timer dismisses only the notice, never the saved dislike. Retain manual dismissal, undo and failure feedback. Replacing a notice or changing accounts cancels prior timers. Keep all notice timers/state in memoized leaves; no root playback-tick or countdown state.
