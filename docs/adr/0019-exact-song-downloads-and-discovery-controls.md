# ADR 0019: Recording-bound downloads and reversible discovery controls

Implemented on `codex/jiosaavn-playback-experiment`, 2026-10-27, following ADR 0017's cleanup checkpoint and ADR 0018's account-scoped feedback model.

Download buttons dispatch `DownloadTrack` with the displayed track's saved identity. The backend reads that recording's source snapshot and resolves its exact provider ID. It never searches title/artist to choose a replacement recording. Metadata-only legacy wishlist entries retain an explicit Find action; source-bound search results, imported playlists, discovery cards, collections and both players download directly. The options modal is removed.

M4A containing the provider's native AAC audio is the default. This is an ordinary music container and avoids another lossy conversion. The existing bounded Rust transfer/import/event path handles downloading, cancellation and final-file publication. `download_tasks.source_track_id` persists recording identity; its migration recovers older JioSaavn tasks only when their existing filename suffix exactly matches a saved source ID. Download queries attach saved aliases for that source. Concurrent direct clicks reuse an active/completed transfer. Filenames retain a source suffix and bound UTF-8 bytes to fit ordinary filesystems with multilingual titles.

A shared memoized button subscribes to the existing leaf progress emitter. Transfer ticks never update root App state. Percentage and a transform-based fill belong to the exact recording, including its saved aliases; title matching cannot mark another release downloaded. Unknown size starts at zero, byte progress is capped at 99% until final publication, and completed tasks show a downloaded icon with full fill. Failure allows retry. Player buttons are keyed by track identity so a pending request cannot animate a newly selected song.

Not interested is a pressed/unpressed icon backed by durable account preferences. Initial/account/search hydration and account-scoped feedback events update the shared icon state. Pressing again sends RemoveTrackFeedback, restores recommendation eligibility and recomputes taste/scores. Generated suggestions are removed immediately when excluded; explicit search/manual access remains available. Both interfaces expose this control in search, recommendations, collections and the player.

Every Discovery chapter exposes refresh. Personal suggestions re-query taste-based ranking, mixes expire/regenerate through the existing generator, charts bypass their feed cache, and trending refreshes its feeds. Charts retain their real editorial names, IDs, permalinks and images. Live inspection confirmed that JioSaavn reads editorial language from the `L` cookie, while language query parameters alone still return Hindi defaults. Chart entries use both `id`/`title` and `listid`/`listname`. Both shapes are normalized and English/international programming is explicitly requested alongside regional charts. International playlists are shown under the names returned by the service, without inventing worldwide chart positions.

Chart sleeves now display their supplied artwork. Online aliases can request the artwork saved with their exact recording, before unrelated enrichment fallback. Recommendation selection prefers original singles/albums over recognizable compilation duplicates, while keeping artwork, album and audio attached to the chosen ID. Existing displayed recordings are never silently retargeted. Source brands are removed from normal UI labels; internal source identities and technical documentation remain.

Validation is recorded in the dated implementation checkpoint in `docs/jiosaavn-experiment.md`. Fixtures and live downloads use disposable storage. Original audio tags/files and the user's live profile are not changed by these tests.

## Player identity regression follow-up

The first implementation gave the dislike and download components the same track-ID key in the Brutalist tools row. On song changes, React reported duplicate sibling keys and retained orphan dislike controls; a real-App replay grew from one to ten icons. Keys now include the action role (`dislike:<id>` and `download:<id>`) in both players, preserving per-song request isolation without key collisions. Missing or whitespace-only artist metadata displays Unknown Artist when a song is selected; the selection prompt is reserved for an empty player. No artist is inferred from a filename or written back to an audio file.

`scripts/test-player-identity-ui.mjs` reproduces twelve online/local transitions in each presentation, including the missing/blank artist cases. It asserts exactly one dislike button, the correct download-control count and artist text, one backend subscription, and no duplicate-key warnings. The regression failed before the fix and passes afterward. Existing single-song checks did not exercise reconciliation across track identities.
