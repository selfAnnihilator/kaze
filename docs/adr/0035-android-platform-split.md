# Android platform split: shared core, desktop shell, and the kaze-media plugin

Kaze ships one Tauri 2 codebase. Desktop (Linux, macOS, Windows) was the only target, and
its shell (`run()`, plugins, tray, updater, single instance, autostart, MPRIS, keyring,
native file dialogs) lived in the binary `src-tauri/src/app.rs`. Tauri mobile needs a
`#[mobile_entry_point]` `run()` in a `cdylib` library, and the library had no `run()`. Some
desktop-only crates also fail to build for `aarch64-linux-android` (`rfd` is the one
confirmed failure).

Decision:

| Area | Rule |
| --- | --- |
| Shell location | The Tauri shell moves into the library. `src-tauri/src/lib.rs` exposes `run()` with `#[cfg_attr(mobile, tauri::mobile_entry_point)]` on Android. `app.rs` is a thin `main()` that calls `platform::desktop::preconfigure()` and then `run()`. The desktop binary is still `kaze`. |
| Platform modules | `platform/shared.rs` holds the IPC commands, the artwork protocol and the async runtime, and is compiled on every target. `platform/desktop.rs` (with `platform/desktop/`: tray, lifecycle, startup, Linux helpers, window chrome, webview tuning) is gated `not(any(target_os = "android", target_os = "ios"))`. `platform/android.rs` is gated `target_os = "android"`. |
| Cargo gating | `rfd`, `tauri-plugin-updater`, `tauri-plugin-single-instance` and tauri's `tray-icon` feature are desktop-only. `tauri-plugin-kaze-media` is Android-only. The `cdylib` and `staticlib` crate types are added next to `rlib`. |
| Core backend | CoreProcessor, PlaybackService, SQLite/sqlx, recommendations and the scanner stay shared and unchanged. Platform differences enter only through cfg seams: base directories (`AppConfig::with_base_dirs`), the secret store (`cloud/secret_store.rs`), and the avatar picker (`ProfileService::pick_avatar_file`, which returns `Ok(None)` on mobile). |
| Audio | All audio stays in Rust. rodio, symphonia and cpal play through AAudio (via the oboe dependency that cpal pulls in on Android). No WebView `<audio>` or `new Audio(...)` is added, which keeps the one-queue, one-state-machine rule from `AGENTS.md`. |
| Media session | The `kaze-media` plugin never plays audio. Kotlin `PlaybackService` (Media3 `MediaSessionService`) mirrors Rust playback state into a `SimpleBasePlayer`-based session. It provides the notification, lock-screen and headset/Bluetooth controls, and audio focus. It holds a partial wake lock while playing and runs with the `mediaPlayback` foreground service type. Transport commands return to Rust as `mediaCommand` events and are dispatched into CoreProcessor. |
| Plugin layout | `plugins/kaze-media/` is a Rust crate (`tauri-plugin-kaze-media`, `register_android_plugin`) plus a Gradle library under `android/`. The Kotlin code has `KazeMediaPlugin`, `PlaybackService`, `SecretStore` (EncryptedSharedPreferences with an AES-256 Keystore master key) and `FolderPicker` (`ACTION_OPEN_DOCUMENT_TREE`). |
| Playback events | `platform/media_bridge.rs` maps EventBus events to a `MirrorUpdate`. The mapping is pure and tested on the host. Position ticks are not pushed; the session extrapolates while playing. |
| Android project | `src-tauri/gen/android/` is generated by Tauri and committed. The manifest declares `READ_MEDIA_AUDIO`, `READ_EXTERNAL_STORAGE` (maxSdk 32), `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `WAKE_LOCK` and `POST_NOTIFICATIONS`, plus the `PlaybackService` declaration. |
| Desktop behaviour | Unchanged. Same paths, keyring, dialogs, tray, updater and MPRIS. The refactor commits move code without behaviour changes. |

Consequences:

- The desktop and Android shells differ in `platform/`. The shared core does not change
  for platform reasons.
- Clippy and tests must run per target, because the moved modules change dead-code and
  unused-import results by cfg.
- Kotlin and Gradle files sit outside `npm run audit:conventions` (which scans Rust and
  TypeScript). They still follow the 500-line limit by convention.
- The Keystore bridge (`KeystoreStore` delegating to `PluginSecrets`) and the `android_pick_music_folder` command are wired in Rust. Frontend use of the picker, SAF-aware scanning and on-device verification are still open. These are listed in `docs/ANDROID.md`.
  Until they are wired, Android credentials fall back to the private 0600 file and the
  music folder is not chosen through SAF.

Alternatives:

- Kotlin or WebView audio (`<audio>` or ExoPlayer for playback). Rejected: it would split
  playback into two state machines and break the unified-playback rule.
- A separate Android repository or workspace. Rejected: it would duplicate the core and
  split the shared IPC contract.
- Keeping `run()` in the binary and adding a second entry point for mobile. Rejected:
  Tauri mobile needs the entry in a `cdylib` library.
