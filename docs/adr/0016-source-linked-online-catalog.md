# ADR 0016: Online songs retain the exact source version shown

Status: implemented on the JioSaavn testing branch, 2026-10-27. Supersedes title-based online playback matching and the manual-search redirect from ADR 0015. Conservative enrichment of physical local files is unchanged.

The shared failure was metadata-only iTunes/online identities entering Home, Flow, saved collections and restored queues. Their synthetic durations (often 210 seconds) and duplicate provider releases made later title matching fail. A search redirect did not repair that identity contract.

Every online track-bearing query is now prepared by OnlineCatalog before presentation. New JioSaavn identities retain the provider song ID. Older saved identities are linked once to a playable JioSaavn result with matching title/artist; the album is preferred and provider ordering breaks alternate-release ties. The selected provider's complete metadata becomes the displayed snapshot, including actual album, artwork and duration. Unavailable candidates are omitted from playable results while original saved rows remain in the database.

`online_track_sources` persists the provider ID and metadata snapshot for each stable Kaze identity. Stable IDs preserve playlists, likes, history and statistics. The binding table allows multiple saved IDs to reference one provider song without rewriting the unique provider/provider-ID pair in external_tracks. Search reuses an existing JioSaavn identity when that source was already saved under a non-prefixed ID. Cloud ingestion of older labels cannot change this device's chosen source: the snapshot restores canonical labels. IPC includes `playback_source: { provider: "jiosaavn", track_id: "<provider song ID>" }`. Neither temporary audio URLs nor the URL envelope are persisted in the source snapshot. Cloud restore normalizes noncanonical JioSaavn provider pairs to `online` / stable Kaze ID, preserving the exact source link before a canonical row claims the provider pair. Existing noncanonical owners are converted in the same transaction as the incoming row. Missing source snapshots use the explicit saved provider ID and metadata without matching; existing selections remain authoritative. This handles independently saved legacy/canonical IDs in either restore order without merging playlist, history or statistics identities.

Playback and metadata-only pre-resolution read the saved source ID. They do not search titles, choose another release or require a unique catalog match. Expired media URLs refresh only by that same provider ID. The audio cache remains keyed by the actual JioSaavn ID, so a saved alias and a search selection of that version share the correct audio cache.

Restored queues repair metadata and retain queue-entry identity, selected entry when available, repeat and shuffle order. Unavailable online queue entries are omitted. Queue creation binds sources before mutation; generated Flow/random online candidates must already carry a JioSaavn source. Source preparation precedes the queue-operation lock. Real local paths are excluded from online conversion even if a historical format flag says online. No audio tags are rewritten.

Preparation is limited to four concurrent provider searches, a twenty-second batch deadline, bounded lock/miss maps and a five-minute negative-result cache. Provider requests keep their existing cancellation/time/size limits. Metadata events are batched after presentation/preparation to avoid repeated root refreshes. Source snapshots allow later displays/restarts to use the same version without searching again.

Validation covers two same-name releases, incorrect legacy duration, persistent selection after restart/provider outage, actual cached playback of the shown version, unavailable-row filtering without deleting saved records, queue restoration, account identity and local-file preservation. Opt-in live verification plays saved aliases for Babydoll, Dance With Me, Missing Piece, Bloody Mary and Bad Romance through muted native Rust output and compares playback's exact source and metadata with the displayed item.
