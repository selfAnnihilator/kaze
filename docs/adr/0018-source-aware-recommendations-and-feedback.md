# ADR 0018: Source-aware scores and persistent recommendation feedback

Implemented on the JioSaavn testing branch, 2026-10-27, after source-cleanup commit `6f105cb` (ADR 0017).

`recommendations/signals.rs` provides account-scoped recording identities, accumulated listening and feedback across saved aliases and provider releases. Source IDs preserve the fetched version for playback; normalized title/artist credits connect saved aliases and alternate releases for recommendation preferences. Primary artist credits allow collaborations to inherit listening affinity without requiring identical database artist IDs. Source metadata supplies language and release year; missing values remain unknown, and language is not invented as a genre. Shared recording play/completion/skip/like signals feed local recommendations and Flow. Discovery drops old chart/preview availability bonuses and uses listening, artist, language, genre where known, recording performance and feedback. Home For You now includes source-ready online songs.

Not interested is a strict exclusion, separate from its softer effect on artist/language/genre affinity. It applies before selection/fallback in local recommendations, discovery, Flow and generated mixes, and again after source preparation in recommendation query responses. Upcoming matching queue entries are removed; random continuation and next/finish transitions exclude hidden songs, including repeat-one. Current audio is not interrupted. Explicit search, direct playback, original files, manual playlists and listening history remain available. Related releases/aliases with matching title and overlapping artist credits share exclusions; unrelated covers do not become an artist ban.

`recommendation_feedback` stores the explicit account choice independently of mutable statistics and caches. Local explicit choices use monotonic timestamps, and Allow again or Like changes all known related preference keys and compatibility flags. Imported negative cloud flags are captured into durable preferences; subsequent neutral counter snapshots cannot erase them. Existing cloud song-stat feedback remains the compatibility transport. An imported choice is sticky on that device until an explicit local Allow again/Like action; the independent preference table is not a new bidirectional server collection. No cloud server deployment is required or performed. Guest claiming transfers explicit preferences along with existing account data.

The backend materializes a fetched online song before accepting feedback, so songs need not have played first. Mutations keep original track IDs/counters/history, remove related Liked Songs membership and cached smart-mix membership, expire generated mixes, update the queue, invalidate Home and publish account-scoped feedback/taste events. Frontend buttons appear in Home, discovery cards, collection rows and both players. A confirmation offers Allow again. Feedback never dispatches playback. Recommendation request guards prevent older asynchronous responses from reinstating removed cards. Progress remains in the existing leaf emitter; no high-frequency root state, browser audio, new blur or unbounded lists were added.

Initial validation before the follow-up controls work passed 203 Rust regressions (eight optional/manual tests ignored), fourteen Node test files, both interface feedback/removal/Allow again checks, buffering and delayed-result scoring checks, and frontend/native builds. Dedicated backend coverage checks saved aliases, future releases/credit variants, account isolation, score reduction, generated mixes, queue removal, manual playlist/direct lookup preservation, feedback before playback, cloud restoration/stale neutral snapshots, guest transfer and explicit re-enabling. Live gates verify progressive full-song playback, pause/resume, seek, exact cache identity, actual provider charts/playlist import and a selected full-audio download decoded by Kaze. Tests use disposable storage; real-profile preferences are not changed.

A native desktop run initially failed its MPRIS Playing assertion during hide/restore after the first six groups passed. The rerun was temporarily blocked by an automatic approval-review usage limit. After its stated reset time, the same assertion and all ten hide/restore cycles passed, along with the full eleven-group desktop gate. The intermittent cause remains unconfirmed; the assertion now includes cycle, MPRIS status and backend state on failure. It was not weakened or removed. The latest controls/download verification is recorded in ADR 0019 and the dated experiment checkpoint.
