# Kaze 2.1.1

## Queue

- Songs you add to the queue now play next, right after the current song and ahead of the playlist or recommendations. Several play in the order you added them, then the rest of the queue continues. Adding a song the app had already queued further down moves it up.
- Search results, the top search result and Discover cards have an add-to-queue button. It never interrupts what is playing.
- Starting a playlist or collection replaces the queue with that playlist. Recommendations follow once it ends.
- Clear queue removes only the upcoming songs; the playing song keeps playing.
- The ✓ on queue buttons marks songs you queued.

## Player

- Shuffle now lives only on collection screens (Local, Downloads, playlists, Liked). Its place in the Brutalist deck opens the queue, and the Spatial bar drops it.
- The song title in the deck opens the collection it is playing from (a playlist, Liked, a mix or chart, Local or Downloads). Songs from Flow, search or Discover show a plain title; the cover still opens Now Playing.
- Liked Songs no longer shows the "Already in collection" bookmark.
- Home's previous sleeve stays empty on the first song of the queue.

## Build

- Development builds optimise the image libraries, so local covers appear promptly in `tauri dev`. Release builds are unchanged.

## Verification

400 Rust tests (14 ignored), 97 Node tests and 31 browser checks across both interfaces passed, with clippy and the conventions audit clean. The saved queue keeps loading from 2.1.0; the new enqueue field is optional, so no database migration is needed.
