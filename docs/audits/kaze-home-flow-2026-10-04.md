# Kaze Home + Flow audit — 2026-10-04

Independent inspection and repair of the current uncommitted implementation. No commit, push, reset, checkout, or unrelated revert was performed. Existing v1.0.6, MPRIS, seek guards, unified playback, and liked-song handling were retained.

1. **Architecture found.** React uses `src/services/api.ts` to invoke Tauri's generic command/query handlers in `src-tauri/src/app.rs`. `CoreProcessor` dispatches to services, repository abstractions and SQLite. `PlaybackService` owns the audio backend and the existing `PlaybackQueue`; `HistoryService` consumes playback events with session IDs. Ranking and local recommendations already have their own reusable primitives. Flow introduces no browser audio, second audio backend, or second queue.

2. **Original Flow approach.** Gemini added `FlowEngine`, Home/Flow commands and queries, an account-keyed settings record, a memoized Home view, player explanations, and refill branches in explicit Next and natural completion. Start played one recommendation and individually enqueued the remainder. Scoring and explanations were separately implemented inside Flow rather than reusing the recommendation scorer.

3. **What was correct.** The feature was routed through existing IPC and native playback. Recommendations were based on real SQLite fields, not acoustic or invented mood metrics. Generating recommendations did not directly log playback. Home's primary hierarchy was Flow, Recent Rotation and Rediscover, with For You and a compact weekly summary below. Home lists were bounded to small section sizes, and no new blur surfaces or progress ticks were introduced in root state. Signed-out playlist filtering matches the existing logout test and was retained after checking that account boundary.

4. **Problems confirmed.** Refills hardcoded the guest account and ratio `0.5`, ignoring authenticated users and steering. Stop only changed a persisted flag, while source-based refill continued. Continue restarted playback and appended another batch. Manual playback left stale Flow settings/origin, and frontend queue restoration could reinsert generated entries deliberately removed by the backend. Flow allowed online placeholders longer than 30 seconds despite its local-library intent. Zero-limit generation could return a track. Explanations had an artist-name/artist-ID mismatch, duplicated rules, unsupported favorite/unheard claims, assumed missing timestamps, and a string/object response mismatch in the player modal. Home did not refresh with playback, and cover URLs pointed at an unavailable `/api/cover/` route. Queue generation and playback commits lacked sufficient ordering against newer intent. The old session could also accumulate non-playing resolution time before its next start event. The date-dependent statistics test still contained a hardcoded month and could collide with its earlier-date fixture on the first of the month.

5. **Files repaired.** `src-tauri/src/recommendations/flow.rs`, `src-tauri/src/playback/service.rs`, `src-tauri/src/core/processor.rs`, `src-tauri/tests/flow_tests.rs`, `src-tauri/tests/stats_and_account_tests.rs`, `src/App.tsx`, and `src/components/views/HomeView.tsx`. Trailing blank lines were cleaned in `recommendations/mod.rs` and `src/types.ts`. The original command/query additions, Sidebar navigation and NowPlayingBar control were preserved. This report is a new audit artifact.

6. **Exact repairs.** Move Flow start/stop/steering and generated-entry ownership into `PlaybackService`, while keeping settings/scoring in `FlowEngine`. Identify generated queue entries by queue ID, preserve manual entries, resume an active Flow, prune only generated upcoming entries on stop/manual selection, and stop adaptive mode on account transitions. Derive current Flow track metadata from the queue and active status from the runtime. Persist preferences rather than a second live queue. Reuse `ScoringEngine`, restrict candidates to local tracks, cap requests at 100, handle limit zero/non-finite steering, add stable ID tie-breaking and improve artist spacing. Consolidate explanations; distinguish generation-time reasons from existing manual queue choices. Correct the modal's string response, resolve artwork through `GetTrackCoverArt`, add Stop Flow, protect UI requests/settings against stale responses, and refresh Home on navigation, track changes and feedback. Remove the extra album playback implementation that relied on a partially loaded title-filtered frontend track list; retain View Album. Fix the date fixture without changing statistics implementation.

7. **Duplicate architecture removed.** Flow's parallel familiarity scorer was replaced by the shared recommendation scorer. Its separate reason-query logic now uses the same proof-based helper as candidate selection. The frontend's redundant replay of the authoritative queue was removed. Home's For You no longer creates recommendation-session records on each view refresh. No second playback or queue implementation existed to remove.

8. **Scoring after audit.** Let `r` be familiarity `[0,1]`, `F` be the existing `ScoringEngine::score_track` score, `D` the Flow rediscovery value, and `P` an excess-skip penalty. Flow score is `max(0, [r + 0.2(1-r)]F + (1-r)D*d - P)`. Shared `F` uses artist affinity (0.35), genre affinity (0.25), era affinity (0.10), completion rate (0.20; unplayed neutral 0.5), like (+0.25), taste-matched exploration (+0.20), recent-repeat multipliers (0.50/0.70/0.85), and forgotten-favorite bonus (+0.15). `D` uses actual last-played age: 60+ days +0.50, with +0.30 for liked/repeated tracks; 21+ days +0.35; 7+ days +0.15. Never-played tracks get +0.40, with +0.25 when known artist/genre affinity exceeds 0.15. `d` is 0.20/0.50/0.80/1.0 for less than 1/3/7 days/older; it applies to rediscovery, since `F` already includes shared recency handling. `P = min(0.35, 0.05*(skips-completions))` only when skips exceed both two and completions. Dislikes are excluded. No bitrate, duration-based taste or energy signal is claimed. Artist spacing/caps are relaxed when the remaining library cannot satisfy them. Deterministic IDs resolve ties. Tests demonstrate actual ranking reversal and refill steering.

9. **Queue/playback after audit.** Start creates up to 20 selections in the existing queue; exhausted Flow refills up to 15. Manual upcoming entries retain priority/order. Next, Previous, shuffle and repeat use the existing queue methods. Refills exclude up to 40 recent queue tracks and carry the preceding artist into selection. Small libraries can reuse older tracks after that exclusion yields no candidates, but the current track stays excluded during refill. A library with only the current eligible track stops at exhaustion rather than switching to random/disliked/online tracks. Stop Flow ends adaptive generation and removes its upcoming entries; current audio can continue. Explicit playback outside Flow exits adaptive mode. Settings affect subsequent batches, not already queued choices.

10. **History/statistics safety.** Generation, previews, Home reads and steering create no playback-history, playback-journal or track-statistics entries. Real starts still generate unique session IDs only after successful backend playback. Actual interruption now emits `PlaybackStopped` for the prior session when audio stops, before preparation of the next source. `HistoryService` still owns meaningful-play thresholds, skip/completion handling, account ownership, crash recovery and persistence. The active session token now carries its queue-entry identity to guard natural completion against pending selection changes. No history thresholds or repository accounting were weakened.

11. **Concurrency.** A service operation mutex orders generation and queue transitions and protects final playback commits. Audio source network resolution runs outside that mutex; generation and queue identity checks reject superseded work before backend/session changes. Automatic completion checks its generation and queue identity before advancing, so newer manual choices supersede it. Empty-queue stopping occurs inside the same operation rather than racing a newer start. No extra Flow background task or frontend generator exists. Generated ownership/reason bookkeeping is bounded across refills. Home/session requests have revision checks; steering is debounced 250 ms and pending local changes are not overwritten by older reads. No synchronous lock is held across Flow database awaits. The operation mutex intentionally spans batched SQLite recommendation generation; extremely large-library latency still needs native profiling.

12. **Cold start.** Empty library returns a useful Start error and empty Home sections. Missing statistics/history rows use neutral completion and library exploration with deterministic tie-breaking. Small or one-artist libraries relax diversity without duplicate IDs per batch. Mature fixtures cover steering, feedback, old tracks and exclusion; a separate 1,000-track/1,000-history-row fixture verifies bounded unique batches and unchanged history counts. These are functional fixtures, not memory/latency benchmarks.

13. **Why this track.** Selection and lookup share deterministic code with category strings and data-supported text; no AI-generated text. A forgotten track is not automatically called a favorite; skipped tracks are not falsely called unheard; missing last-played timestamps do not imply an invented age. Artist affinity uses artist IDs. Runtime reasons explicitly say they describe the generation-time snapshot, so later playback/unlikes cannot make that historical explanation masquerade as current data. Existing queue entries are explicitly identified as preserved queue choices. Unknown tracks return NotFound rather than fabricated library explanations. A typed reason enum could further strengthen serialization in a later cleanup.

14. **MPRIS.** Source inspection confirms Linux methods continue to delegate to the same playback service, including Next/Previous and seek. Its metadata/status/position events still originate from real playback lifecycle events. The six MPRIS unit tests pass, alongside unified local/online queue, repeat, Previous and source-resolution tests. Live D-Bus, media keys, audible native output, buffering and seeking were not manually exercised; unit tests are not a live desktop certification.

15. **Verification.** `npm run build` and `cargo check --bin kaze --manifest-path src-tauri/Cargo.toml` passed. `git diff --check` passed. Relevant suites: library unit tests 32 (including MPRIS, queue and ranking), cloud sync 4, Flow 15, history 3, playback 7, recommendations 5, source resolution 10, statistics/account 15: **91 passed**, plus one intentionally ignored live production migration. No tests were weakened to hide environment failures.

16. **Remaining concerns.** Live desktop interaction and real audio/MPRIS behavior remain unverified. Recommendation generation still reads the local candidate table and 90-day taste history once per batch; Home ranking is cached for 60 seconds and invalidated on local feedback. Library imports/cloud changes can take that interval to appear in cached For You picks. The existing queue retains played history and emits whole-queue snapshots; very long sessions merit profiling and a separate retention decision. Taste calculation retains its pre-existing behavior, including positive low-weight skipped sessions and feedback-influenced affinities; this audit changes Flow's overlay rather than redefining global taste semantics. Restart restores the preference, with Flow inactive until intentionally started; it does not promise exact Flow queue continuation. Flow's Library Moment is retained as a secondary extra, not a new analytics hierarchy. No unsupported performance or end-to-end guarantees are claimed.
