### 1. P2 — Library browsing silently omits tracks after 1,000 and albums after 200

**Impact:** Large libraries appear smaller than they are. Scrolling cannot reach remaining songs/albums. The track count incorrectly describes the loaded page as the indexed library. No deletion was observed; exact library search and opening a known album ID remain possible workarounds.

**Reproduce:**
1. In a disposable profile, index or seed 1,036 distinct valid local WAV paths; open Library → Tracks.
2. Scroll to the end, navigate away/back, and repeat in Spatial and Brutalist.
3. For albums, supply 201 albums with a backend that honors the requested offset/limit; open Library → Albums.

**Expected:** All indexed entries are reachable through windowed paging; displayed totals reflect the full library.

**Actual:** Both native interfaces show `1000 local audio tracks indexed` for 1,036 seeded tracks. Browser fixtures honoring pagination show the same track cap and `200 albums` for 201 albums. There is no subsequent-page loader. Native album truncation was traced through the same query path but not separately seeded/reproduced.

**Evidence:** [native reproduction](2026-10-31-evidence/native-pagination-complete.log), [controlled browser reproduction](2026-10-31-evidence/probes-v3.log), [native probe](2026-10-31-evidence/native-pagination.py), [browser probe](2026-10-31-evidence/probes.mjs).

**Affected code:** `src/App.tsx:618` requests offset 0/limit 1000; `src/App.tsx:632` requests offset 0/limit 200; the library navigation effect at `src/App.tsx:1818` repeats the first-page request. `src/components/views/LibraryView.tsx:307` labels `tracks.length` as indexed tracks. Rust `src-tauri/src/core/processor.rs:2375`/`:2438` honors pagination. LibraryView and AlbumsView virtualize only the provided array.

**Why existing checks missed it:** `tests/fixtures/dualInterfaceBackend.mjs:229` ignores GetTracks pagination and returns all 1,036 rows; its album catalogue has only 130 entries. The passing bounded-rendering checks do not establish completeness.

**Fix direction:** Load successive pages while retaining windowed DOM rendering and request-generation cancellation; keep catalogue totals separate from loaded-page length. Apply the same completeness contract to albums. Cover a real paginated backend response in regression verification.

### 2. P2 — Failed playlist creation loses the draft and gives no error

**Impact:** Users believe creation completed or cannot tell why the playlist is missing. Retrying requires retyping the name. This loses an unsaved draft, not an existing persisted playlist.

**Reproduce:**
1. Use a signed-in controlled fixture in either interface. Open Library → Playlists → New Playlist.
2. Type `Audit unsaved draft`. Delay CreatePlaylist by 300 ms, then reject with a storage error.
3. Submit Create Playlist.

**Expected:** Keep the dialog/name until success; show an error and permit retry after failure.

**Actual:** The dialog closes immediately and the name is cleared. No visible error appears. The rejected promise produces an unhandled `pageerror` (`AUDIT storage failure`). No playlist is created. Independently repeated in both interfaces; native storage-failure injection was not performed.

**Evidence:** [first probe](2026-10-31-evidence/probes-v3.log), [repeatable probe source](2026-10-31-evidence/probes.mjs), [Spatial screenshot](2026-10-31-evidence/spatial-playlist-failure.png), [Brutalist screenshot](2026-10-31-evidence/brutalist-playlist-failure.png). The earlier independently executed v2 probe produced the same result; only v3 is retained as the final browser evidence.

**Affected code:** `src/components/views/PlaylistsView.tsx:36` types the asynchronous callback as returning void; `:165–175` invokes it without awaiting, then resets/closes. `src/App.tsx:2185` implements an asynchronous handleCreatePlaylist and dispatches CreatePlaylist without handling a rejection locally.

**Fix direction:** Await the asynchronous result, disable duplicate submits while pending, keep the draft/dialog on rejection, show a useful retry message, and close only after confirmed creation.

## Harness failures and suspected risks

- **Two obsolete browser command assertions:** original search-flow-controls-ui expected Pause + ContinueFlow; library-moment-ui expected Pause/Resume. Production now sends authoritative TogglePlayPause. Temporary copies changing only the command assertions passed both styles, including search final-row access, Flow behavior and exact album opening. Original failures remain counted; [corrected search log](2026-10-31-evidence/search-flow-controls-ui-corrected.log), [corrected moment log](2026-10-31-evidence/library-moment-ui-corrected.log). No product change was needed.
- **Native restoration fixture drift:** original test inserts `Saved Track` into SQLite for an untagged `one.wav`; scanning presents `one`. Matching expectations to filenames lets local restoration pass both styles, preserving paused position (~37s), queue, volume, MPRIS and history count. Its later cached-online setup mutates a local row into `online://one` and writes an old `full:v2` cache identity; current playback uses bound JioSaavn identities and `full:v3:jiosaavn:<id>`. The selected track disappears at that stage. This unsupported synthetic identity does not establish a real cached-provider restoration bug; retest with a valid bound identity. [Original failure](2026-10-31-evidence/native-restore.log), [temporary-copy result](2026-10-31-evidence/native-restore-v3.log). Rust restoration tests passed.
- **Native tray fixture drift:** test waits for `Configured Music Folders`, while current Settings exposes `Music Folders`. The timeout is a harness blocker, not proof that Settings is broken. Full standalone lifecycle coverage was not reached.
- **Startup reduced-motion risk:** original interface-startup suite stopped after eight passing groups when it observed a running `color` CSS transition on `.app-startup-brand` in a reduced-motion scenario. This is a measured animation-contract concern; a material visible failure was not established. An independent unchanged rerun passed all startup scenarios, including reduced motion, failed-code cancellation, settings retry and standalone studies; [repeat log](2026-10-31-evidence/interface-startup-repeat.log). Treat this as intermittent pending a targeted visible reproduction. Later scenarios in the original run were not reached.
- **Native memory:** previous wiki audit recorded +89.1 MiB private memory over a 21-minute soak. This audit did not reproduce or resolve that result. Current stable DOM/render counts do not establish stable native memory or absence of allocation leaks.
- **Other silent mutation failures:** Add-to-playlist catches only console errors in App; this is a static risk pending dedicated rejection reproduction, not a third confirmed finding.
